# 按投注时间匹配连续开奖

本次变更用实际历史开奖匹配替代预测期号锁定。新投注保存号码、倍数、追加、实际投注时间和连续期数；时间省略时使用服务端保存时刻。页面可填写北京时间，API 使用带时区的 ISO 时间，数据库统一保存 UTC。

匹配按实际开奖日期升序进行，只保留销售截止时刻严格晚于投注时刻的记录，再取最早 N 次。大乐透优先使用官方当期截止时刻；数据未提供时按当期规则补齐，双色球采用北京时间 20:00。例如 2026-10-28 18:45 的大乐透三期投注可以计入当天；21:00 起的投注跳过当天，包含停售后但尚未开奖的间隙。

官方开奖同步与投注匹配分离，匹配首先消费 SQLite 开奖缓存。需要更早历史的新投注或旧记录可按需回填；历史列表每页 100 条，读取到覆盖投注日期为止，上限 50 页，成功覆盖范围持久保存，后续重试和重启复用。保留投注日期前最近一期校验连续性，防止漏掉首期。分页中断、缺期、未审核的中间期或历史范围不足时暂缓，不使用较晚开奖记录补位。同批同彩种共用查询。

实际开奖不足 N 次时，界面显示剩余待匹配位置，后续任务继续补齐。已匹配前缀不得被重试悄悄更换，缺失奖金保持待补全，不跳到后面开奖。期号与结果在同一事务中写入，重复请求不累计奖金，任何本条投注写入失败均整体回滚。

旧数据库会自动增加 `match_mode`、`placed_at` 字段。旧记录继续按已经保存的明确期号验奖，保持原结果；无法把旧登记时间可靠地认定为实际购买时间，因此不自动重算旧记录。API 明确提供 `issues` 时继续使用该兼容模式。

休市、跨年和临时开奖调整随真实历史记录处理，不再维护未来开奖日历。页面保存不需要先访问开奖接口。验奖由 Go 服务内置调度执行，启动立即补查，默认北京时间每天 22:00 至次日 00:00 每 20 分钟检查（只包含午夜边界，不含 00:20）。`CHECK_ENABLED`、`CHECK_SCHEDULE`、`CHECK_TIMEZONE` 可配置。上游同步即使没有投注也运行，按“彩种 + 窗口”持久保存完成状态，午夜属于前一天窗口。只有官方列表最新开奖已审核，并且全部官方奖级金额完整才停止该彩种本窗口的轮询；双色球需一至六等奖，大乐透现行需一至七等奖、历史规则需一至九等奖及一、二等奖追加奖金。官方列表最新一期即使日期早于窗口日期，只要审核及全奖级金额完整，也完成本窗口同步；投注未中奖或奖金为 0 不替代官方数据完整性判断。官方列表没有最新记录、最新记录未审核或奖金缺失时继续同步。完成窗口重启复用缓存，下一窗口重新发现官方开奖。本地连续投注尚未公布的未来期数不导致已完成窗口继续请求上游；必要的历史覆盖回填与窗口停止条件独立。旧 HTTP 任务接口已移除，升级时停用已有外部调度。

验证包括截止前后一毫秒、停售到开奖的间隙、跨年、分页首期缺口、奖金补全、幂等、混合分页、数据库升级/重启、删除竞态、事务回滚和浏览器保存流程。
