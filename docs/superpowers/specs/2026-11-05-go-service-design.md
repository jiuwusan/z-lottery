# Go 服务与内置验奖调度

> 状态：第一阶段 Go 迁移已验证；下述官方开奖窗口同步更正为当前要求，更正实现与验证仍待根任务完成。原“按投注金额完整停止上游检查”的规则已废弃。

## 目标

将 Node.js 后端整体改写为 Go，将定时验奖放在同一服务进程内直接执行，不再依赖外部调度器或 HTTP 触发链接。保持现有列表、弹窗新增、随机选号和投注数据可用。

## 方案与边界

采用 Go HTTP 服务、SQLite 持久化和进程内调度。浏览器继续使用现有 HTML/CSS/JavaScript；浏览器随机选号无需后端重写。保留 Node.js 服务并增加 Go 调度器会留下双运行时和外部调用依赖，不符合整体迁移目标；重写前端框架也不改善本次调度需求。

直接在当前分支修改。不自动提交、推送或部署。

## 兼容要求

- 兼容原 SQLite 数据库路径、表结构、投注与验奖结果 JSON，原有命名卷可继续挂载。通过旧格式数据库验证迁移读取、继续验奖、删除及重启持久化。
- 保持 `/api/health` 和投注增删查分页接口的现有响应格式、校验、状态码及金额精度上限。
- 保留历史明确期号记录与按日期匹配记录；保持截止时间边界、连续实际开奖匹配、历史数据完整性与冲突检查。
- 保留复式奖级组合计算、大乐透历史规则切换、追加奖金、奖金缺失待补全、跨期合计精度校验和重复验奖幂等性。
- 保留官方请求超时、响应大小限制、未审核开奖过滤及失败记录重试，防止上游异常写入错误匹配结果。
- 保留现有前端与独立选号 CLI；生产服务和容器运行不再依赖 Node.js。删除旧后端后，将仍有价值的行为用例迁到 Go 测试。

## 内置调度

- 默认启用；以 `Asia/Shanghai` 时区执行，默认每天 22:00、22:20、22:40、23:00、23:20、23:40、次日 00:00 检查。
- 上游同步与本地投注匹配分离。即使没有投注，也按彩种发现官方已发布的最新开奖；默认窗口为当日 22:00 至次日 00:00，午夜属于前一天窗口。
- 仅当官方最新开奖 `Ready` 且 `OfficialAmountsComplete` 时，停止该彩种本窗口后续上游轮询。双色球要求一至六等奖；大乐透现行规则一至七等奖、历史九奖级规则一至九等奖，并要求一、二等奖追加金额。不得根据投注记录的 `winAmount`、命中奖级完整或未中奖金额 0 判定同步完成。
- 官方列表没有最新记录、最新记录未审核、缺少任一官方奖级或上游失败时，窗口内继续重试。官方列表为唯一依据，最新一期日期早于窗口日期也可完成本窗口同步，非开奖日不等待假想的当日记录。不推测今日或下一期期号，不硬编码开奖日历。
- 使用 `draw_sync` 按彩种与窗口持久保存完成状态。相同窗口重启补查跳过已完成的网络同步，进入下一窗口重新发现开奖。
- 投注匹配与验奖使用持久化开奖缓存；未来尚未公布的连续期数不迫使已完成窗口继续发起 HTTP。新回溯投注或旧明确期号记录需要更早覆盖时，允许一次必要的历史回填并持久保存覆盖范围；历史回填与当前窗口是否继续轮询相互独立。
- 提供环境变量配置是否启用、调度表达式和时区，校验配置错误并在启动时明确报错。
- 启动后立即补查一次，复用当前窗口持久化状态与缓存；随后按设定时间执行。同步后遍历本地待检查投注，保证已缓存开奖、奖金更新和失败记录能够继续处理。
- 同一时间只运行一轮，慢任务跨过下一触发点时跳过重叠轮次；单条或单个彩种上游失败不阻止本轮其他记录处理，失败留待下一轮重试。
- 服务停止时取消网络请求和任务，等待任务退出后关闭数据库；HTTP 请求与后台调度并发访问 SQLite 时保持事务完整性。
- 记录启动配置、每轮开始/结束、批次统计、失败与重叠跳过日志，不输出整份投注数据。

## 移除外链调用

移除 `/api/jobs/check` 路由、`server/check-job.js`、页面验奖链接及复制逻辑。页面改为简短说明验奖由服务自动执行，不增加新的手动触发入口。

## 部署与文档

使用 Go 多阶段构建和非 root 运行镜像，打包静态页面、SQLite 运行依赖与时区数据。沿用容器端口 3000、宿主机端口 3100、数据卷与健康检查，更新 Compose、环境变量示例及 CI。CI 同时验证 Go 测试、仍保留的选号测试、镜像启动和卷内数据重启持久化。

文档写明升级前备份数据库、保留原数据卷、移除原外部 cron/调度平台任务，以及新的内部调度配置。迁移不主动修改实际部署环境。
