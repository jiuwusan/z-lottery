# 静态号码生成页面

整个 `lottery` 目录可以直接部署，包含 `index.html`、`favicon.svg`、`styles.css`、`lottery-core.js`、`app.js`、`records.js`、`install.js`、`manifest.webmanifest` 和 `icon-180.png`、`icon-192.png`、`icon-512.png`。离线选号不需要安装依赖、构建、后端接口或外部 CDN，也可以双击 `index.html` 本地使用。投注持久化和自动验奖需要后端服务。

## 添加到桌面

页头提供“添加到桌面”按钮。Chrome/Edge 等浏览器提供原生安装事件时，点击按钮打开系统安装确认；尚未提供事件、用户取消或安装窗口失败时，显示手动添加指引。浏览器可能要求用户先交互并停留一段时间才提供原生安装事件。

- 电脑：Chrome/Edge 可安装为独立窗口应用；桌面、开始菜单和应用列表的位置由系统和浏览器决定。需要桌面图标时，可通过浏览器的应用管理创建快捷方式；Mac Safari 支持时使用“添加到程序坞”。
- 安卓：原生安装，或从浏览器菜单选择“安装应用／添加到主屏幕”。
- iPhone/iPad：使用分享菜单的“添加到主屏幕”；如有“作为网页 App 打开”，开启它。找不到入口时请使用 Safari。微信等内置浏览器会提示先使用系统浏览器打开。
- 已在独立应用窗口打开，或当前页面收到安装完成事件后，隐藏安装按钮。浏览器页面无法通用检测所有已安装应用，不把点击确认或本地存储标记当作安装完成。

安装应用需要 HTTPS；电脑开发可以使用 `http://localhost` 或 `http://127.0.0.1`。手机通过局域网普通 HTTP 地址访问不满足原生安装条件，需要使用手机可访问的 HTTPS 地址。`file://` 仍能选号，但不能安装网页应用。安装及手动添加均需要用户确认。

manifest 使用相对 `start_url`、`scope` 和图标地址，省略 `id` 使应用身份默认采用实际启动地址，避免同源不同子目录的应用身份冲突，兼容 `/` 与 `/lottery/` 等带尾斜杠的部署目录。子目录反向代理仍需剥离前缀；不带尾斜杠的目录地址应由代理重定向为带斜杠地址。静态部署要包含所有新增文件，并将 `.webmanifest` 的 Content-Type 设为 `application/manifest+json`（Go 服务已显式设置）。

安装图标保留现有 `favicon.svg` 的骰子图案和颜色，输出 180、192、512 像素 PNG，背景铺满以适应系统裁切。未引入 service worker 或离线缓存；添加桌面图标不会离线保存投注记录，记录和验奖仍需连接后端。

页面默认展示投注列表，点击「新增投注」在弹窗中设置、生成并保存号码。保存成功后关闭弹窗并刷新列表；保存失败时保留输入并提示错误。支持关闭按钮及 Esc 关闭，手动关闭后再次打开会保留本次内容；保存请求期间暂时禁止关闭以免遗漏结果。

投注详情按每笔记录判断：一期都没有开奖结果时显示独立的“投注号码”区块；已有任意一期开奖结果后不再显示该区块，即使还有后续未开奖期数。逐期开奖号码、命中情况及验奖结果继续保留，奖金待补全也属于已有开奖结果；仅匹配到期号不会提前隐藏。

验奖由 Go 服务内置调度执行，无需复制链接或配置外部任务。启用后启动立即补查，默认北京时间 22:00 至次日 00:00 每 20 分钟检查（不含 00:20）。官方最新开奖审核通过且全部官方奖级金额公布完整后，停止该彩种本窗口的上游轮询；官方列表没有最新记录、最新记录未审核或金额不全时继续等待。官方列表最新一期可以早于窗口日期，非开奖日无需等待当日开奖。午夜属于前一天窗口，重启保留完成状态，下一窗口重新同步。投注从本地开奖缓存匹配，尚未公布的未来期数不会延长已完成窗口的轮询；即使没有投注也同步开奖。调度配置见 [服务说明](../server/README.md)。

支持大乐透与双色球、单式/复式、多组、共享号码、倍数、连续期数和大乐透追加。默认值与 Go CLI（`cmd/lottery`）一致。页面打开时不自动生成，点击「生成号码」后才显示号码和金额并启用复制。恢复默认设置只重置参数，不生成号码。切换彩种会恢复该彩种的选号数量并清空共享数量；切换至双色球时取消追加。修改设置后，点击生成才更新号码和金额，复制的也是已生成结果。

浏览器使用 `crypto.getRandomValues` 和拒绝采样生成均匀随机数。共享号码是最低交集；其他位置也可能偶然重复，各组分别计费。页面每次最多生成 1,000 组，超出 JavaScript 安全整数精度的金额会被拒绝。不提供预测或购买功能；验奖由连接的后端服务提供。

选号区域数值设置使用「− / ＋」步进器，每次调整 1，无需键盘输入。达到上下限时对应按钮禁用；减少选号数量时，共享数量同步限制在选号数量以内。调整参数不会自动生成号码。

配置区与生成操作之间保留独立间距，切换双色球或显示错误不会贴住输入框。手机连续期数始终占满一行；380px及以下字段改为单列，避免数值被加减按钮挤压。触控环境的次要操作按钮至少44px，记录操作在空间不足时换行。

“新增投注”直接使用随机选号表单：配置参数 → 生成号码 → 保存投注。连续期数为 1～100，保存已展示的同一批号码、倍数、追加状态和期数。可填写实际投注时间（北京时间），留空使用服务端保存时刻；不能填写未来时间。保存不依赖官方开奖接口，也不提前锁定预测期号。

验奖任务从持久化缓存按日期升序读取历史开奖，只有投注时间早于当期销售截止时间才计入，选取最早的连续 N 次实际开奖。截止时刻及其后的投注从下一期开始；休市、临时调整及跨年跟随真实记录。开奖不足时保留待匹配位置，已匹配期号和结果持久保存。修改设置后重新生成才能保存，同一次生成保存后禁用保存按钮。

## Nginx 部署

以上为离线选号模式。页面新增“投注记录”管理区，需要运行 Go 后端并转发同源 `/api/`，配置见 [服务部署说明](../server/README.md)。静态部署时仍可正常选号和复制，记录功能需连接服务。

例如，将此目录的全部内容复制到 `/var/www/z-lottery/`，使用以下配置（替换域名）：

```nginx
server {
    listen 80;
    server_name lottery.example.com;
    root /var/www/z-lottery;
    index index.html;

    charset utf-8;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

确保 Nginx 的 `http` 配置中包含 `include mime.types;`，然后运行 `nginx -t` 并重载 Nginx。

也可以复制到现有站点根目录下的 `lottery/` 文件夹，通过 `/lottery/` 访问。页面所有资源都使用相对路径，无需修改代码或配置前端路由回退。

复制结果包含彩种、选号规格、倍数、期数和各组号码，追加投注时倍数显示为“1倍追加”等文案，不包含共享数量、注数或金额。号码按两位数字显示，以空格分隔，各组之间留一个空行。复制按钮优先使用安全上下文的 Clipboard API，普通 HTTP 或本地文件尝试浏览器的兼容复制方式；若浏览器禁止复制，会提示手动选择复制。

## 验证

在项目根目录运行：

```bash
go test ./...
```

浏览器选号源码由纯 Go 的 goja 引擎执行测试，覆盖默认配置、随机选号、共享号码、金额计算和非法参数，并与 Go CLI 的选号实现交叉验证。

UI间距回归运行 `node --test test/browser-spacing.cjs`，需独立的Playwright开发环境；`PLAYWRIGHT_NODE_MODULES` 指向其安装目录，`CHROME_PATH` 可指定Chrome/Chromium。默认查找临时目录下的 `z-lottery-browser-check`，不把开发依赖装入运行镜像。测试仅提供本机静态文件和合成API，覆盖15档屏宽、两彩种及错误/保存/列表/安装状态。可用 `LOTTERY_BROWSER_ARTIFACTS` 指定截图目录，详细步骤见[开发规范](../docs/development.md)。
